# Product Management System

A simple full-stack Product Management application built with React, Node.js, Express, and MongoDB.

## Technologies Used

- Frontend: React and Vite
- Backend: Node.js and Express
- Database: MongoDB Atlas
- ODM: Mongoose

## Product Fields

Each product contains:
- ID (automatically generated by MongoDB)
- Product name
- Category
- Price (ETB)
- Quantity
- Description

## Features

- Create products
- View all products
- View a single product by ID
- Update products
- Delete products
- Validate product information
- Handle errors
- Store data persistently in MongoDB
- Seed five fictional products
- API test page with valid and invalid requests

## Installation

1. Clone or download the project.
2. Open the project folder in a terminal.
3. Install dependencies:

```bash
npm install
```

4. Create a `.env` file in the project root:

```env
MONGODB_URI=your_mongodb_connection_string
PORT=5000
```

Replace the example connection string with your own MongoDB connection string.

## Running the Application

Start the backend:

```bash
node src/sever/server.js
```

Start the frontend in another terminal:

```bash
npm run dev
```

Open the local frontend URL shown by Vite.

## Seed the Database

Run:

```bash
node src/sever/seed.js
```

The seed script inserts five fictional products when the collection is empty.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/products` | Create a product |
| GET | `/api/products` | Get all products |
| GET | `/api/products/:id` | Get one product |
| PUT | `/api/products/:id` | Update a product |
| DELETE | `/api/products/:id` | Delete a product |

## API Test Page

Open:

`http://localhost:5173/test.html`

Use the buttons to test CRUD operations and invalid product data.

## Validation Rules

- Product name is required.
- Category is required.
- Price must be greater than zero.
- Quantity cannot be negative.
- Quantity must be a whole number.

## Database Persistence

Products are stored in MongoDB. Data remains available after restarting the backend.

## Environment Variables

Never commit your `.env` file or expose your MongoDB credentials. The project uses environment variables for database configuration.
